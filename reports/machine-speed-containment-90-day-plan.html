How it works

Every alert takes one of three paths

The containment list

Auto

Contained in seconds when a near-certain detection fires. Starts with every workstation and standard user.

Limited

Stop the process, block the site, sign the user out, then page. Default for servers until the owner signs off.

Human only

Domain controllers, hypervisors, identity, backup, security tools, break-glass and root accounts.

Engineering

To-do by phase

Days 1–30 · see, investigate, authorize

  • Run the blind spot skill: record the tech stack, then check logs and detections against it
    • EDR, SIEM, identity, cloud, edge, automation
    • Map each to the logs and detections it needs
    • Gaps reported with an owner
    • Later: verify the stack against the wiki / CMDB
  • Get critical logs into the SIEM: under 5 min delay, alert if any go silent
    • EDR alerts and telemetry
    • EDR sensor health + a second "host alive" source
    • EDR console audit (policy, exclusions)
    • Identity sign-ins, including MFA
    • Identity audit and risk detections
    • Domain controller security logs
    • Edge device admin logins and config changes
    • Cloud control plane and threat findings
    • Decoy file read auditing
  • Stand up the triage agent, read-only: it investigates high alerts and writes up the case; analysts act
  • Build an internet-facing systems inventory the triage agent uses: vendor, version, owner, exposed services
  • Send edge device admin logins and config changes to the triage agent
  • Deploy decoys in testing mode, each with its trigger
    • Decoy files: a program opens one to read it (ignore AV, backup, indexing)
    • Fake credentials: any sign-in attempt that uses them
    • Decoy AD accounts: any logon or Kerberos ticket request
    • Once live: isolate the machine, sign out its user
  • Draft the containment policy in week 1; get it signed by day 30
  • Put every workstation and standard user on the auto list; servers start as limited
  • Define human-only accounts by rule, checked live before any action
    • Admin roles and groups (IdP, AD, cloud)
    • Non-human: service, sync and workload accounts
    • Break-glass and cloud root: a short fixed list
  • Stand up the action log: help desk can see why a user or machine was contained, and undo it
  • Start phishing-resistant MFA rollout for admins
Exit: first blind spot report · triage agent writing cases · policy signed · action log live
Engineering

To-do by phase, continued

Days 31–60 · build actions, learn the noise

  • Add safety to every action: list check, one-click and bulk undo, rate limits that page on-call
  • Call the EDR's built-in isolate and kill-process actions from automation, with the safety checks
  • Build and test: block a domain or IP at DNS, proxy or firewall
  • Build and test: sign out everywhere, disable account, reset password and MFA
  • EDR on 95%+ of machines in block mode with anti-tamper; review exclusions
  • Switch decoys to live; if they fire on more than 3 machines in 15 min, stop auto-isolating and page
  • Testing mode: credential theft, MFA fatigue, machine-speed recon, ransomware prep
  • Triage agent recommends actions on every testing-mode detection; analysts approve or reject
  • Weekly: review each false positive; fix the rule or exempt that exact host, program and account, with an owner and end date
  • Ask each server owner: can we isolate this server automatically? No answer stays limited
Exit: every action run and undone on a test target · decoys live · every high alert investigated

Days 61–90 · cloud, go live

  • Cloud: revoke stolen credentials safely; auto-restore disabled logging
  • Cloud detections: logging turned off, keys used outside the cloud, new admin or root use
  • EDR tampering: act only with a second signal; test the outage circuit breaker
  • Inventory AI agents that can send, change or run code
  • Review each tested rule; switch the ones that pass to live
  • Let the triage agent act on workstations for actions it got right in 95%+ of 30 cases
  • Phishing-resistant MFA on 100% of admins
  • Run the attack simulation; record detect-to-contain time
Exit: 9 detections live · detect-to-contain measured · scorecard to CISO

Thresholds to configure

  • Testing period: ≥ 2 weeks per rule
  • Go live when: ≤ 1 false positive / month, fired once
  • AI agent acts when: 30 cases · ≥ 95% agree · 0 harmful
  • Rate limits: per rule + per action → stop + page
  • EDR outage breaker: > 2% sensors silent / hour → no auto
  • Decoy mass-hit pause: > 3 machines / 15 min → stop auto, one incident, page
  • Not on the list: treat as limited
  • Exceptions: narrowest match · owner · ≤ 12 months
  • Targets come from: alert fields only, never free text
  • Auto actions: only on the auto list

For the CISO

Automated containment for AI-speed attacks in 90 days

Decision needed: approve a written policy that lets automation contain a short list of near-certain attacks on low-risk targets without waiting for an analyst. Sign by day 30.

Problem. AI-assisted attackers reach lateral movement in minutes (fastest observed eCrime breakout: 27 seconds, CrowdStrike). When every containment needs an analyst decision, response arrives after the damage.

What changes by day 90.

  • 9 detections contain automatically on workstations, standard users and human cloud accounts: decoy and canary hits, credential theft, MFA fatigue, machine-speed reconnaissance, ransomware preparation, cloud logging disabled, stolen cloud credentials, and EDR tampering confirmed by a second signal.
  • All other high-severity alerts get an AI-agent investigation and recommendation in under 5 minutes. Analysts still decide.
  • Exposure reduced: phishing-resistant MFA for all admins, edge device management off the internet, actively exploited vulnerabilities on exposed systems patched within 72 hours.

What could go wrong, and the control.

RiskControl
Automation isolates the wrong targetLow-risk targets only; critical systems and accounts go to a human. 2 weeks recommend-only first. One-click undo.
Bad rule or vendor outage causes mass actionRate limits stop automation and page on-call; circuit breaker pauses it if many EDR sensors fail at once.
An attacker triggers our automation against usMass decoy hits become one investigation, not mass isolation. Text planted for the AI agent never triggers containment.
The AI agent makes a bad callRecommend-only until ≥ 95% agreement with analysts over 30+ cases, zero harmful calls, per action type.
Users don't know why they were cut offEvery action logged; help desk answers "did security do this to me?" in under a minute.

4. Safety mechanics

ControlSetting
Recommend periodEvery rule ≥ 2 weeks recommend-only on real traffic before auto
Rule graduationProjected ≤ 1 false positive/month (or each covered by a narrow exception); action tested; fired at least once (real or simulated); listed in the signed policy
Agent graduationPer action type and tier: ≥ 30 reviewed recommendations, ≥ 95% agreement, zero harmful, passes prompt-injection test set
Rate limitsPer rule and per action type (isolate, disable, revoke, block). Hitting a limit stops automation and pages P1
EDR circuit breaker> ~2% of sensors (or N hosts) silent within an hour → infrastructure incident, no automated action
Decoy mass-hit breakerDecoys tripped on > 3 hosts within 15 min → stop per-host containment, one P1 incident, find shared source
Decoy read filterCount shells, script engines, editors, archivers, AI agent processes; exclude backup, AV, indexer, Explorer preview/thumbnail
Prompt injectionContainment targets come only from structured alert entities and independent telemetry, never free text
Missing dataUntagged host = B, untagged identity = B, stale table row = missing
ExceptionsNarrowest match (hash + host + account first), owner, reason, expiry ≤ 12 months, human-approved

8. Edge devices

  1. Inventory every exposed VPN, firewall, file transfer and remote access gateway: vendor, version, owner, what it authenticates against.
  2. Lock down: management off the internet, VPN via SSO + MFA, named admins only, unused portals off.
  3. Patch known-exploited vulnerabilities in ≤ 72 h, or mitigate / restrict / take offline with a signed exception.
  4. Assume compromise when a known-exploited bug hits an exposed device: run the vendor integrity checker, review admin accounts, config, files and VPN sessions since disclosure, reset credentials that passed through it (VPN users in the window, the device's LDAP account).
  5. Watch admin sign-ins, config/firmware changes and admin account changes; route to triage.

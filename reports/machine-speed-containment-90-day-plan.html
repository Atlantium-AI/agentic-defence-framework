Executive summary

Attackers now move at machine speed. Our response has to as well.

AI-driven attackers can go from first access to impact in minutes. CrowdStrike's fastest observed eCrime breakout time is 27 seconds. When every containment decision waits for a person, defenders lose that race by design.

This plan pre-approves a small set of reversible containment actions, fired automatically by high-confidence detections, on low-risk targets first. An AI triage agent investigates everything else in minutes. It runs on tools you already own: EDR, SIEM, identity provider, cloud consoles and an automation platform.

How attacks get in

Three ways in, one response rule

Pulled in

Brought in by a user or AI agent

Phishing, downloads, fake fixes, a prompt-injected AI agent. Starts on workstations.

Pushed in

Exploited from the internet

VPNs, firewalls, web apps. The top breach vector. Starts on servers and edge devices.

Walked in

Valid access, misused

Stolen passwords and sessions, MFA abuse, vendor access. Starts in the identity provider.

Once inside, attackers get the keys, blind the guards, move, then cash out. Our rule is simple: cut off whatever they're using. If it's a host, isolate it. If it's an identity, kill its sessions. If it's a cloud key, revoke it.

The 30 / 60 / 90 day plan

From permission to proven, in three phases

Phases are balanced by effort. The first month is light on engineering because signatures, owners and inventories take calendar time.

Days 1–30

See and authorize

  • Containment policy signed by leadership
  • Every workstation marked safe to auto-isolate; servers default to page-a-human
  • Action log live: the help desk can answer "did security do this to me?"
  • Critical logs confirmed flowing
  • Internet-facing systems inventoried; edge management taken off the internet
  • Decoy files, fake credentials and decoy accounts deployed
  • Read-only AI agent reports blind spots
Exit: policy signed, workstations tagged, first blind spot report delivered
Days 31–60

Build actions, learn the noise

  • Response actions built and tested with one-click undo: isolate, stop a process, block a site, sign out everywhere, disable, reset credentials
  • EDR in block mode everywhere, coverage gaps closed
  • Decoys go fully automatic
  • Other detections run in recommend-only mode
  • AI triage agent writes up every high-severity alert, risky sign-in and new MFA registration
Exit: every action proven, decoys automatic, every high alert investigated in minutes
Days 61–90

Cloud, edge, go automatic

  • Azure and AWS: disabled logging restored automatically, stolen cloud credentials cut off
  • Edge device admin and config changes investigated
  • Detections with a clean record go automatic for low-risk targets
  • Phishing-resistant MFA for every admin
  • Safe simulated attack measures detect-to-contain
Exit: 8 detections automatic, time to contain measured, board scorecard

Safety by design

Automation that can't take the business down

  • Recommend first. Nothing acts on its own until it has run two clean weeks in recommend-only mode.
  • Low-risk targets only. Workstations, standard users and human cloud accounts. Critical systems always go to a person.
  • One-click undo and bulk undo on every action, plus rate limits that page on-call when hit.
  • A full action log, so anyone can find out in a minute whether security acted on them, and why.
  • Our tools can't cause an outage. A circuit breaker pauses automation during an EDR vendor outage, and tampering alerts need a second signal.
  • Attackers can't turn it against us. Mass decoy hits become one investigation, not mass isolation.
  • Prompt injection never triggers containment. Text planted for our AI agent goes to an analyst, not to an action.
  • The AI earns autonomy one action at a time: ≥ 95% agreement with analysts, zero harmful calls.
